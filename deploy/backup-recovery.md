# Backup, restore and rollback

Local Phase 10 archive backup remains private and checksummed: `server/.private-archive/course-reset/catalog.json`. It preserves full BSON Extended JSON. Its archive restore intentionally restores only touched course/lesson records; it is not a general point-in-time database restore.

A **native BSON** rehearsal is implemented: `node server/scripts/backup-rehearsal.mjs`. It can connect only to fixed localhost disposable databases created by that invocation. It dumps seven sanitized fixture collections (accounts, archived lessons, notes, private table messages, quizzes, review attempts and progress), verifies SHA-256, restores BSON documents and unique indexes into another isolated database, checks learning-record references, then drops only its own two fixture databases. Files are 0600 in a 0700 temporary directory. Both `mongodump` and `mongorestore` must be installed. No production records are fixtures. The Phase 19 local rehearsal passed; this does not verify cloud backup scheduling, encryption or hosted recovery.

For deployment, configure managed snapshots or scheduled `mongodump --config PRIVATE_CONFIG --archive=PRIVATE_FILE --gzip` with a read-only backup account. A private YAML/JSON tools configuration keeps the URI/password out of command arguments. Use encrypted off-device storage and separate key access; local file permissions are not off-device encryption. Set retention and recovery objectives with the owner before launch (suggested starting policy: seven daily, four weekly; not yet active). Restrict backup access and audit restores. Logical dumps need a maintenance window or an appropriate replica-set snapshot strategy to ensure cross-collection consistency.

Restore with a temporary restore principal into a **new isolated database** using `mongorestore --config PRIVATE_TARGET_CONFIG --archive=PRIVATE_FILE --gzip --nsInclude='SOURCE.*' --nsFrom='SOURCE.*' --nsTo='ISOLATED_TARGET.*' --stopOnError`. First verify the checksum and destination, rehearse counts/indexes/access, then review a controlled cutover. Never run `--drop` against a live production database as a routine test. MongoDB tool configuration and namespace support: [mongodump](https://www.mongodb.com/docs/database-tools/mongodump/), [mongorestore](https://www.mongodb.com/docs/database-tools/mongorestore/).

Production startup disables automatic Mongoose index creation. Prepare indexes explicitly with `node server/scripts/prepare-indexes.mjs --database EXACT_NAME`. It creates required indexes without dropping indexes/documents. Legacy `(language, day)` uniqueness requires the backed-up Phase 10 `publication-index` migration first. No production migration has run.

Rollback: keep the previous verified frontend artifact and API image/commit, plus release metadata, host configuration and a pre-migration backup. Re-deploy matching versions, verify `/readyz`, auth, course publication restrictions, Study SSE and static assets. Do not roll back to pre-Phase-10 code that ignores archival publication flags. Code rollback does not restore database contents or undo indexes. Restore data only after reviewing later student writes and approving the cutover. Deployment and destructive production restoration still require explicit owner approval.

## Phase 20 catalog preparation — no reset executed

Run `node server/scripts/course-reset.mjs inventory --database EXACT_NAME` against an explicitly authorized database. It is read-only and reports collection/publication counts and active lessons without printing account records, course bodies or media URLs. The local Phase 19 inventory found no course records, 56 archived lessons and zero active lessons. A production catalog inventory is still required; local counts are not production evidence.

If the authorized active catalog is already empty, do not run a reset. Otherwise take a fresh checksummed private backup, verify isolated recovery, pause course authoring, and review the existing guarded `archive` operation. It archives only course/lesson publication metadata; it does not delete student accounts, enrollments, learning records, notes, goals, groups or media. Review the affected count and backup batch before executing any Phase 20 operation. `restore` checks archive markers and independent edits before replacing only archive-touched records; it is not a general restore of historical student writes. Public media cleanup is a separate reviewed operation and is not included.
